# Лекция 8. Хеш-таблицы

Лекция по теме **hash tables** (хеш-таблицы) на основе идей из книги *«Грокаем алгоритмы»* Адитьи Бхаргавы.

## Зачем нужны хеш-таблицы

Представьте, что цены на товары лежат в книге.

- Книга не отсортирована: чтобы найти «апельсины», приходится проверять почти всё. Это **O(n)**.
- Книга отсортирована: можно использовать бинарный поиск. Это **O(log n)**.
- А хочется как у «Мэгги», которая мгновенно помнит цену любого товара, то есть примерно **O(1)**.

Хеш-таблица даёт эту магию: по ключу мы быстро находим значение. Обычно это **O(1)** в среднем, но при плохой хеш-функции или перегрузке таблицы операции могут деградировать.

## Хеш-функция

**Хеш-функция** получает строку (вообще любые данные, то есть последовательность байтов) и возвращает число, обычно индекс массива.

Ключевые требования:

1. **Последовательность (детерминированность)**: один и тот же ключ всегда даёт одно и то же число.
2. **Разные ключи желательно распределять по разным индексам** (хорошее распределение).
3. **Хеш-функция учитывает размер массива** и возвращает только допустимые индексы.

## Как из массива получается хеш-таблица

Идея простая:

- берём массив фиксированного размера (слоты);
- хешируем ключ и получаем индекс;
- кладём значение в слот (или в «корзину» этого слота).

В результате обращение по ключу выглядит так:

1) посчитать `index = hash(key)`  
2) взять значение из `array[index]`

## Коллизии

**Коллизия** случается, когда два разных ключа попадают в один и тот же индекс.

Реальная хеш-таблица обязана уметь жить с коллизиями. Самые частые стратегии:

- **цепочки (chaining)**: в каждом слоте хранится список значений;
- **открытая адресация (open addressing)**: при занятости слота ищем следующий подходящий.

В среднем операции остаются быстрыми, если таблица не перегружена.

## Где хеш-таблицы уже есть

Почти во всех языках это стандартная структура:

- Python: `dict`
- JavaScript: `Map` (или объект, но `Map` лучше для общего случая)
- Java/C#: `HashMap` / `Dictionary`

### Мини-пример (Python)

```python
book = dict()
book["авокадо"] = 1.49
price = book["авокадо"]
```

### Мини-пример (JavaScript)

```js
const book = new Map();
book.set("авокадо", 1.49);
const price = book.get("авокадо");
```

## Где реально применяют

- кэширование (cache)
- подсчёт частот (frequency counter)
- быстрые проверки «видели ли мы это раньше» (dedup)
- индексы в базах данных (на уровне идеи)
- мемоизация в рекурсии (memoization)

## Практика

1) Реализуйте простую хеш-таблицу на массиве с chaining (массив корзин).  
2) Сделайте «книгу цен»: `add(name, price)`, `get(name)`, `remove(name)`.  
3) Задача на частоты: посчитать, сколько раз встречается каждый символ в строке.  
4) Задача на коллизии: придумайте набор ключей, которые бьют в один индекс (для вашей хеш-функции) и проверьте, что структура не ломается.

# Хеш-функция на примере IP-адреса веб-сайта

## Что такое hash function

**Хеш-функция (hash function)** — это функция, которая получает на вход **key** и преобразует его в число, по которому можно быстро найти место хранения данных.

Проще говоря:

- у нас есть **ключ**
- хеш-функция превращает его в индекс
- по этому индексу данные кладутся в **hash table**

Идея очень практичная. Вместо того чтобы каждый раз перебирать всё подряд, мы стараемся сразу попасть в нужную ячейку.

---

## Пример из жизни интернета

Когда пользователь вводит в браузере адрес сайта, например:

```text
google.com
```

компьютеру недостаточно просто имени сайта. Для соединения нужен **IP address**.

Например, в ответе DNS можно увидеть такие адреса:

```text
google.com → 142.250.151.113
google.com → 142.250.151.101
google.com → 142.250.151.138
```

Или IPv6-адреса:

```text
google.com → 2a00:1450:4009:c17::8b
```

Здесь важно понять одну вещь:

**DNS** связывает **domain name** и **IP address**.

Это очень похоже на идею хеш-таблицы:

- **key** = имя сайта
- **value** = IP-адрес

То есть:

```text
google.com → 142.250.151.113
```

По смыслу это такое же отображение, как:

```text
Jenny → 8675309
apple → 120
cat → 4
```

---

## Где тут именно хеш-функция

Важно не путать две вещи:

1. **DNS** — это реальная система доменных имён в интернете.
2. **Hash function** — это алгоритмический механизм, который помогает быстро находить данные по ключу.

DNS в реальной жизни сложнее, чем учебная хеш-таблица. Но для понимания темы пример очень удобный.

Представим, что у нас есть небольшая таблица, где мы хотим хранить адреса сайтов.

| Domain name | IP address |
|---|---|
| google.com | 142.250.151.113 |
| youtube.com | 142.250.74.206 |
| openai.com | 104.18.33.45 |

Теперь вопрос.

Как быстро понять, куда положить `google.com`?

Вот тут и нужна **hash function**.

Она берёт строку `google.com` и возвращает число, например:

```text
hash("google.com") = 4
```

Это может означать:

- сохранить запись в ячейку с индексом `4`
- потом искать `google.com` сразу в этой области

Тогда схема будет такой:

```text
hash("google.com") = 4
таблица[4] = "142.250.151.113"
```

Когда снова приходит запрос `google.com`, программа не перебирает всю таблицу. Она снова считает хеш:

```text
hash("google.com") = 4
```

и сразу идёт в нужную ячейку.

Вот в этом и кайф хеш-таблицы. Очень быстро. Без тупого полного перебора.

## Упрощённый пример

Допустим, у нас есть очень маленький массив из 10 ячеек.

Наша учебная хеш-функция делает что-то вроде:

1. берёт символы строки
2. переводит их в числа
3. складывает
4. берёт остаток от деления по модулю `10`

Например:

```text
hash("google.com") = 7
hash("youtube.com") = 2
hash("openai.com") = 7
```

Тогда получится так:

- `google.com` идёт в ячейку `7`
- `youtube.com` идёт в ячейку `2`
- `openai.com` тоже идёт в ячейку `7`

И вот тут мы подходим к важной проблеме.

## Коллизия

**Collision** или **коллизия** — это ситуация, когда **разные keys** получают один и тот же индекс.

Например:

```text
hash("google.com") = 7
hash("openai.com") = 7
```

Получается, что две разные записи хотят попасть в одну и ту же ячейку.

Это и есть **collision**.

Коллизии не означают, что хеш-таблица сломалась. Это нормальная часть жизни любой **hash table**.

Главное, чтобы структура данных умела с этим работать.

Обычно используют один из подходов:

- **chaining** — хранить в одной ячейке список элементов
- **open addressing** — искать следующую свободную ячейку

---

## Почему пример с IP хорошо объясняет тему

Потому что он показывает идею соответствия:

```text
domain name → IP address
```

Человек запоминает `google.com`, а машина работает с адресом вроде `142.250.151.113`.

Для быстрого поиска удобно хранить такие пары по принципу:

- есть **key**
- есть **value**
- нужно получать **value** очень быстро

Это именно тот класс задач, где хеш-таблицы особенно полезны.

Они хороши, когда нужно:

- быстро искать по ключу
- быстро добавлять данные
- быстро проверять, существует ли запись

---

## Важное уточнение

Нельзя говорить, что **хеш-функция превращает имя сайта в IP-адрес**.

Это будет неверно.

Правильно так:

- **DNS** сопоставляет имя сайта и IP-адрес
- **hash function** помогает быстро определить место хранения данных внутри **hash table**

То есть:

```text
google.com → IP-адрес
```

это **mapping** в системе DNS,

а вот:

```text
hash("google.com") = 4
```

это уже работа хеш-функции внутри структуры данных.

Это две разные идеи, хотя учебный пример с DNS отлично помогает понять, зачем вообще нужны хеш-таблицы.

---

## Короткая формула для запоминания

**Hash function** не ищет значение сама.

Она:

- получает **key**
- вычисляет индекс
- помогает быстро обратиться к данным

На примере сайта:

```text
key = "google.com"
value = "142.250.151.113"
hash("google.com") = индекс ячейки
```

---

## Мини-вывод

**Хеш-функция** — это способ быстро преобразовать **key** в индекс массива.

На примере веб-сайтов удобно представить, что:

- имя сайта `google.com` выступает как **key**
- IP-адрес выступает как **value**
- хеш-функция помогает быстро найти, где это значение лежит в **hash table**

Если два разных сайта попадают в одну и ту же ячейку, возникает **collision**.

Именно поэтому тема хеш-таблиц всегда идёт рядом с темами:

- **speed / performance**
- **collisions**
- **fast lookup**

---

## Короткая версия для запоминания.

**Хеш-функция (hash function)** получает ключ и преобразует его в индекс массива. Это нужно для быстрого поиска данных в хеш-таблице. На примере веб-сайтов можно представить, что имя сайта является ключом, а IP-адрес значением. Например, `google.com` можно связать с `142.250.151.113`. Важно понимать, что имя сайта в IP-адрес преобразует система **DNS**, а хеш-функция не делает DNS-преобразование, а лишь помогает быстро определить место хранения пары `key → value` внутри **hash table**. Если разные ключи получают один и тот же индекс, возникает **collision**.
